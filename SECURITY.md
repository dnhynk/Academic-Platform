# Security policy

This repository contains a functional, synthetic-only Phase 1 local core, not a production vault. The default lane creates throwaway profiles backed by plaintext bundled SQLite and must not process real personal data until ADR-002 is accepted.

Report suspected signing, canonicalization, authority-resolution, fixture-integrity, or dependency issues privately to the repository owner. Do not attach real academic records, audio, private source code, access tokens, or secrets to a report; use a minimal synthetic reproduction.

The implemented boundary verifies deterministic CBOR, an independently expected Ed25519 device key, and the signature before append-only acceptance. The daemon opens one profile as its sole canonical writer, serves current-user local IPC over a protected Windows named pipe or Unix-domain socket, and admits only the allowlisted synthetic fixture. The local core includes migrations, canonical tables, a plaintext vault, disposable projections, deterministic export, consistent plaintext backup, verified restore into a new empty profile, deep doctor checks, and crash-replay evidence. It does not provide accepted encryption at rest, production key management, process sandboxing, secure deletion, or an egress broker; the default policy remains `storage_encryption=NONE`, `production_data_allowed=false`, and `adr_002_accepted=false`. Five-platform SQLCipher evidence and macOS, Android, and iOS `phase1-exit` evidence remain open, so real or production data is forbidden.
