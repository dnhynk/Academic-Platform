# ADR-011: Monorepo, toolchain, CI, and release

- Status: Accepted baseline; release acceptance remains open

## Decision

Use one Cargo workspace and one pnpm workspace without Nx, Bazel, Docker, or a remote cache. Rust 1.98.0 with rustfmt/clippy, Node 24.19.0, and pnpm 11.22.0 are exact pins. Bootstrap and Rust doctor consume one committed conformance corpus: Node/pnpm output must equal the exact token, while rustc/cargo may append only ordinary parenthesized stable commit/date metadata after the exact version token. Prerelease, nightly, longer-prefix, wrapper, and locally modified spellings fail. `Cargo.lock` and `pnpm-lock.yaml` are committed. Cross-platform workflows are Cargo, pnpm, and small Node scripts rather than a PowerShell/bash-only build graph.

Windows native and Linux are required CI environments for core tests and fixture replay. Each native fixture verify/replay/emit/diff command is an independent workflow step so PowerShell cannot overwrite an intermediate native failure; a topology mutation recreates and rejects the masked-failure shape. A checkout-only source-preflight job runs before tool/dependency setup, and every Rust/frontend executable job depends on it. The same preflight is the first bootstrap action before fetch or install. It uses only Node built-ins and checked-in parsers: the Cargo gate structurally parses TOML package sources across legal quote, key, whitespace, multiline, inline, and escape spellings; the pnpm gate parses a bounded fail-closed YAML profile and traverses importers, packages, snapshots, and every top-level default/named catalog. YAML anchors, aliases, and tags are rejected on block and flow mapping keys before decoding. Scalar dependency entries and nonempty object subsets containing only string `specifier`/`version` fields reject Git source types/repositories/schemes/hosts/hosted shorthands plus insecure HTTP tarballs independent of quoting or flow/block serialization; empty, unknown-field, wrong-type, duplicate, malformed, or unsupported lock structures fail closed. The allow/reject fixtures retain pnpm v11 registry, sparse registry, workspace, link, path, npm-alias, peer-snapshot, and ordinary local-file forms. A synthetic local-Git regression proves the rejected anchored bytes remain consumable by real frozen/offline pnpm. GitHub Actions use full commit SHAs, `contents: read`, bounded timeouts, and no credential persistence.

Git-backed pnpm spellings include the `gist:` hosted shorthand and URLs whose canonical hostname is `gist.github.com` or `codeload.github.com`; these are denied in every traversed importer, package, snapshot, resolution, and default/named catalog form. Canonical hostname comparison is case-insensitive, removes a trailing dot and a single `www.` prefix, and does not reject ordinary registry, workspace, link, file, peer-snapshot, or npm-alias references.

## Implemented evidence

Workspace manifests, locks, line-ending/format rules, doctor/bootstrap scripts, full locked commands, and Windows/Linux CI are present. CI hash-pins and verifies/replays the byte-immutable v1 fixture, v1 JSON Schema, and v1 Proto through the deterministic reader, deterministically emits/diffs/verifies/replays the current v2 fixture, validates committed JSON through raw lexical checks, Draft 2020-12 schemas, and semantic parity, cross-checks Rust/Protobuf.js wire types, cardinalities, oneofs, tags, and a byte golden for both Proto versions, executes structural Cargo/pnpm source negatives including catalogs, and hashes the exact LF canonical-spec bytes. Docker is not used. The repository has no remote, and Phase 0 does not publish an artifact.

The preflight has no third-party parser dependency and therefore cannot be delayed by dependency installation. Its Cargo and pnpm mutation corpora run again after install as part of the deterministic security baseline.

## Acceptance gates

Fresh Windows one-command bootstrap rehearsal; architecture-specific native dependency matrix when storage/UI arrive; SBOM and license/advisory policy; signed installer and OS code signing; updater signature negative test; protected release environment; provenance; and secret/capability/plaintext-canary CI.
