# ADR-011: Monorepo, toolchain, CI, and release

- Status: Accepted baseline; release acceptance remains open

## Decision

Use one Cargo workspace and one pnpm workspace without Nx, Bazel, Docker, or a remote cache. Rust 1.98.0 with rustfmt/clippy, Node 24.19.0, and pnpm 11.22.0 are exact pins. Bootstrap and Rust doctor consume one committed conformance corpus: Node/pnpm output must equal the exact token, while rustc/cargo may append only ordinary parenthesized stable commit/date metadata after the exact version token. Prerelease, nightly, longer-prefix, wrapper, and locally modified spellings fail. `Cargo.lock` and `pnpm-lock.yaml` are committed. Cross-platform workflows are Cargo, pnpm, and small Node scripts rather than a PowerShell/bash-only build graph.

Windows native and Linux are required CI environments for core tests and fixture replay. The topology gate parses the workflow through the duplicate-rejecting bounded YAML parser and requires the exact ordered OS matrix `[ubuntu-latest, windows-latest]`, an exact `runs-on: ${{ matrix.os }}` binding, no include/exclude or unreviewed matrix dimension, and all six ordered native fixture verify/replay/emit/diff commands as independent workflow steps. Required source-preflight, Rust, and contracts jobs and every one of their steps must omit `if` and `continue-on-error`. Mutations cover fixed or broken runners, missing/duplicate/extra OS entries, Windows exclusion, disabled jobs and steps, job/step failure tolerance, duplicate required job and step keys, and the multiline masked-failure shape. A checkout-only source-preflight job runs before tool/dependency setup, and every Rust/frontend executable job depends on it. The same preflight is the first bootstrap action before fetch or install. It uses only Node built-ins and checked-in parsers: the Cargo gate structurally parses TOML package sources across legal quote, key, whitespace, multiline, inline, and escape spellings; the pnpm gate parses a bounded fail-closed YAML profile and traverses importers, packages, snapshots, and every top-level default/named catalog. YAML anchors, aliases, and tags are rejected on block and flow mapping keys before decoding. Plain YAML null, boolean, decimal/binary/octal/hex integer, float, date, and timestamp scalar kinds are preserved; they fail wherever direct dependency, `specifier`, or `version` source references require strings, while explicitly quoted lookalikes remain strings. Scalar dependency entries and nonempty object subsets containing only string `specifier`/`version` fields reject Git source types/repositories/schemes/hosts/hosted shorthands plus insecure HTTP tarballs independent of quoting or flow/block serialization. Resolution objects form a closed tagged union: supported pnpm v11 variations recursively validate exact targets and nested resolutions with bounded depth, binary metadata is exact, and every nested URL is inspected. Empty, unknown-field, wrong-type, duplicate, malformed, or unsupported lock structures fail closed. The allow/reject fixtures retain pnpm v11 registry, sparse registry, workspace, link, path, npm-alias, peer-snapshot, runtime-variation, and ordinary local-file forms. Synthetic local-Git and runtime-variation regressions prove rejected bytes remain consumable by real frozen/offline pnpm. GitHub Actions use full commit SHAs, `contents: read`, bounded timeouts, and no credential persistence.

The effective CI verifier additionally pins the complete reviewed top-level, job, and step key inventory and values. This makes checkout followed immediately by dependency-free source preflight the only permitted preflight sequence, forbids custom shells and step/job environment execution context on reviewed run steps, and covers writable permissions, floating action refs, credential persistence, missing or changed timeouts, extra keys, reordering/insertion, and combined mutations. Explicit mapping-key indicators are rejected before decoding in block, nested sequence, flow, and compact flow maps; ordinary and quoted question-mark key controls remain distinct, and a pinned frozen/offline pnpm regression proves the exact nested variation/binary form would otherwise be consumed. The `pnpm run doctor` wrapper invokes locked, offline Cargo, requires a populated cache from prior bootstrap, and performs no network resolution itself.

Git-backed pnpm spellings include the `gist:` hosted shorthand and URLs whose canonical hostname is `gist.github.com` or `codeload.github.com`; these are denied in every traversed importer, package, snapshot, resolution, and default/named catalog form. Canonical hostname comparison is case-insensitive, removes a trailing dot and a single `www.` prefix, and does not reject ordinary registry, workspace, link, file, peer-snapshot, or npm-alias references.

## Implemented evidence

Workspace manifests, locks, line-ending/format rules, doctor/bootstrap scripts, full locked commands, and Windows/Linux CI are present. CI hash-pins and verifies/replays the byte-immutable v1 fixture, v1 JSON Schema, and v1 Proto through the deterministic reader, deterministically emits/diffs/verifies/replays the current v2 fixture, validates committed JSON through fatal UTF-8 plus raw lexical checks, Draft 2020-12 schemas, and semantic parity, cross-checks Rust/Protobuf.js wire types, cardinalities, oneofs, tags, UUID invariants, and a byte golden for both Proto versions, executes structural Cargo/pnpm source negatives including recursive variations, catalogs, and the block/flow scalar-kind matrix, verifies effective unconditional execution on the exact two-runner native topology, and hashes the exact LF canonical-spec bytes. Docker is not used. The repository has no remote, and Phase 0 does not publish an artifact.

The preflight has no third-party parser dependency and therefore cannot be delayed by dependency installation. Its Cargo and pnpm mutation corpora run again after install as part of the deterministic security baseline.

## Acceptance gates

Fresh Windows one-command bootstrap rehearsal; architecture-specific native dependency matrix when storage/UI arrive; SBOM and license/advisory policy; signed installer and OS code signing; updater signature negative test; protected release environment; provenance; and secret/capability/plaintext-canary CI.
